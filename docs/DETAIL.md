# 本地知识库

把本机若干个文件夹变成可检索的知识库，让 AI 在回答时能查到并引用你自己的笔记与文档；配一个侧边栏面板，加库、建索引、测接口、改配置都不用离开界面。

## 它解决什么

模型不知道你硬盘里的东西。这个插件把每个已挂载文件夹（库）下的文本文件切块、向量化、建索引，然后给 AI 三个只读工具和一个能重建索引的工具。AI 回答前先检索，命中后按「库名 + 文件路径 + 行号」引用，需要原文再按路径读。

## 工作方式

1. 扫描 `root`：按后缀过滤，跳过 `node_modules` / `.git` / `.obsidian` 等目录，超过大小上限的文件会记录为“跳过”，不支持的格式按扩展名计数后列出。
2. 取正文：纯文本直接读；`.docx` 走内置的 OOXML 解包（读 `word/document.xml`，按段落拆行，剔除域代码，还原 XML 实体）；`.doc` / `.wps` 走 OLE2 复合文档解析（目录项 → WordDocument/1Table 流 → FIB 片段表 → 按编码解码正文）；`.pdf` 走内置的 PDF 解析（扫描 `obj` 建对象表、解 FlateDecode、按 `ToUnicode` 还原字形、按 `Tj/TJ/Td/Tm` 等文本操作符还原版面）。按文件头判断真实格式，改过后缀的文件也能读，全部不引入第三方依赖。
   没有文本层的扫描件 PDF 会抛带 `scanned` 标记的错误；打开 `ocr.enabled` 时改走 mutool 渲染 + 视觉模型转写（`lib/ocr.js`）：`mutool draw` 出 PNG → 逐页发 `chat/completions`（`temperature 0`，提示词要求完整转写、保留段落顺序）→ 按页拼接。结果按「文件指纹 + dpi + 模型」缓存在 `<indexDir>/ocr/`，同一文件重建不会重复识别；有文本层的 PDF 不会触发 OCR。
3. 切块：Markdown 的 `#` 标题另起一块，块内按字符窗口滑动并保留重叠，每块记录起止行号。
4. 向量化：把片段批量发给 embedding 服务（Ollama 或 OpenAI 兼容端点），向量归一化后与片段一起写入索引目录。
5. 检索：先把问题向量化，按 cosine 相似度排序，再用 `search.minScore` 过滤；分数是真实相似度。关键词兜底则按“查询覆盖率 × 词频/标题加成”算原始分，再经单调饱和映射到 0–1：分数越大越相关，强匹配不会挤在同一个值上导致排序失真。
6. 重排（可选）：召回 `rerank.candidates` 条候选后发给重排模型（Cohere / Jina 协议），按重排分数取前 `topN` 条；重排失败就退回原顺序并在 `note` 里说明，不会让整次检索失败。
7. 增量：重新建索引时，文件大小与 mtime 都没变的片段直接复用旧向量，只对新增和改动过的片段调用 embedding 服务。

embedding 服务连不上时不会让插件失效：索引照样建立（只是没有向量），检索自动退回本地关键词评分，并在结果里说明原因。

批量向量化遇到网关 5xx / 429 / 413 会先退避重试（最多 3 次），仍失败就把这一批拆成两半再发，逐级拆到单条为止——这样一次 12 分钟的重建不会因为中间某一批被上游拒绝而整次作废；成功后在索引元数据里记下 `embeddingSplits` 便于排查。

## 多库

- 配置里 `libraries: [{ name, root, indexDir? }]` 就是库列表；`id` 由 `root` 推算（`lib-<sha1 前 10 位>`），重启后稳定；`indexDir` 默认 `<root>/.dsh-kb`，索引跟着库走，删掉库不影响别的库。
- 每个库各有一个 `KnowledgeBase` 实例（自己的索引、向量、OCR 缓存），外层 `lib/libraries.js` 把它们聚合成和单库一样的接口，多一个可选 `library` 参数（库名、库 id 或 `all`）。
- 检索：默认所有库一起检，每个库按 `max(want, min(40, want*2))` 取候选，合并后按分数排序截断，每条结果带 `library: { id, name }`；某个库出错只在该库记 note，不影响其他库。
- 读文件：不带 `library` 时按路径在各库找，多个库都有同名文件会明确要求指定，不会默默挑一个。
- 重建：不带 `library` 时逐库重建并汇总；带 `library` 只重建那一个。
- 面板里左列顶部是库切换（全部库 / 单库 / ＋ 添加库）；设置页可以增删库（移除只取消挂载，不删磁盘文件与索引）。

## 侧边栏面板

- 入口：左侧栏「知识库」图标（书本），点击进入整页面板；面板与侧边栏按钮用同一个 id（`local-kb`），所以点图标就会选中面板。
- 布局：左列文件清单（筛选 + 片段数），右列三页签。
- 状态标签直接来自 `kb.status()`：文件数、片段数、向量/关键词模式、重排模型、索引是否过期及原因、上次向量化失败原因。
- 设置页的「测试 embedding」「测试重排」分别只发一次请求验证连通性与维度，不重建索引；测的是**表单里当次填写的地址与密钥**（请求体带上 `config` 与表单密钥，服务端现场拼一份临时配置发请求），所以没保存也能先验证。未配置好时返回 400 并说明缺什么（`provider = none` / 未启用重排 / 未配置目录）。「保存设置」通过宿主的 `configEditor` 写回 profile 的 `cordis.patch.yml`，写的是完整配置而不是补丁，插件随即重载，客户端会轮询 `/state` 直到服务恢复；写盘失败时错误记在 `/state.saveError`，页面据此报「设置没有写入存储」而不是报成功。
- 取密钥的顺序是：凭据库记录 → 环境变量（`apiKeyEnv`）→ 配置里的 `apiKey`。界面写密钥只写凭据库，配置文件里只留记录名；界面显示的是掩码，留空表示不修改。
- 凭据服务是**每次用到时现取**（传 getter，不在 `apply()` 抓快照）：宿主重启后插件装配顺序会变，`credentials` 可能晚于本插件就绪，抓快照会得到一次性的 `undefined`，之后所有保存都报「当前宿主没有可用的凭据服务」。若宿主确实不提供该服务，`/state.capabilities.secrets` 为 `false`，设置页会提示改用环境变量（`apiKeyEnv`）。

## 配置

```yaml
- id: local-kb
  name: 'dsh-local-kb'
  config:
    libraries:
      - name: '讲话库'
        root: 'F:\领导讲话知识库'
      - name: '读书笔记'
        root: 'D:\notes'
    embedding:
      provider: ollama
      baseUrl: http://127.0.0.1:11434
      model: bge-m3
    rerank:
      enabled: true
      provider: cohere
      baseUrl: https://api.jina.ai/v1
      model: jina-reranker-v2-base-multilingual
```

- `provider`：`ollama`、`openai`、`none`。`none` 表示只用关键词检索。
- `openai` 模式用 `apiKeyEnv` 指定环境变量名（推荐），也可用 `apiKey` 直接写。
- `rerank.provider` 只影响展示与默认值，请求协议相同：`POST {baseUrl}/rerank`，body `{model, query, documents, top_n}`，响应 `results: [{index, relevance_score}]`。
- `root` 未配置（`libraries` 为空）时插件仍是激活状态，工具调用会返回一条中文配置指引，不会静默失败。只写顶层 `root` 的旧配置会自动当成一条库。

## 四个工具

| 工具 | 用途 |
| --- | --- |
| `kb_search` | 检索片段：返回库名、相对路径、行号、标题、得分、摘要；可用 `path_prefix` 限目录，`mode` 控制语义/关键词，`library` 只查一个库 |
| `kb_read` | 按行读原文，只能读库目录内的文件，越界路径会被拒绝；多库同名文件时用 `library` 指定 |
| `kb_index` | `status` 看索引状态与上次失败原因（多库时逐库列出）；`rebuild` 重建，`force: true` 忽略缓存全量重算；`probe` 只发一次 embedding 请求验证连通性，不重建索引；`library` 只处理一个库 |
| `kb_packet` | 素材包：主题/提纲 → 三通道检索 → 去重 → 四类归集，卡片带路径、行号、年份、地域 |

## 素材包

`lib/material.js` 是纯函数库（不碰 IO），`buildPacket` 负责编排：

1. `buildQueries`：主题与每条提纲点各自生成「语义 + 关键词」两条查询；提纲里出现经济、政治、文化、社会、生态、综合这类领域词时，再加一条 `path_prefix` 定向查询；最后固定补两条 `07-素材金句` 的定向查询（金句、政策表述）。按 `mode|prefix|query` 去重，`packet.points` 限制提纲拆条数。
2. 并发执行所有查询（单条失败进 `failures`，不让整包失败），取回片段后统一加工成卡片。
3. `extractYear`：文件名里的 `20141218_`、`2016年2月14日_`、正文里的年份，取不到时按「十五五/十四五/十三五」推算规划期年份；来源（文件名/正文/未知）一并返回，界面和工具输出都会标出来源，方便判断可信度。
4. `extractRegion`：先看路径（本地/外地地名 → 直接定档），再看正文（本地提及数不少于外地才算本地），再退到全市/全省/部门路径/乡镇名，最后「未标注」。产出 `{level, name, foreign, basis}`，`foreign` 为真时卡片会标「外地 · 地名」。这套是启发式，宁可多标，不可漏标。
5. `classifySnippet`：四类各打分（数据 = 数字 + 单位、政策 = 书名号/部署动词、金句 = 排比与引号短句、事例 = 地名 + 建成/入选/试点），主类目取最高分，其余进 `tags`；`dedupeCards` 把同库同文件 ±6 行内视为同一条，只留高分；`groupCards` 按类截断。

面板的「素材包」页与 `POST /api/local-kb/packet`、`kb_packet` 工具共用同一条链路，区别只在输出形态（卡片 / JSON / 文本）。面板上，结果顶部是一排分类目录卡片（`全部素材` + 有命的类别，各显示条数），点某一类只渲染该类，`全部素材` 回到完整视图；新生成一次自动回到「全部素材」。

## 限制

- 格式：纯文本 + Word（`.docx`、`.doc`、`.wps`）+ PDF（`.pdf`，取文本层）。`.xls/.xlsx` 不解析；扫描件/图片型 PDF 没有文本层，会以“需要 OCR”的原因列进重建结果，不会被静默丢弃。
- PDF 解析是无依赖实现：扫描 `N 0 obj` 建对象表、解压 FlateDecode、解析字体 `/ToUnicode` CMap 把字形码还原成文字，按 `Tm`/`Td`/`T*` 推算位置来补换行与空格；支持多页、`/Contents` 数组、`q/Q` 图形状态栈、内联图片跳过。26 页、13k 字的真实规划稿 51ms 取完。
- OCR（扫描件识图）是可选能力：需要 `mutool`（MuPDF）渲染页面 + 一个视觉模型端点（`ocr.enabled`）；只转写文字，不做版面/图表理解，双栏或表格顺序可能乱；单页约 7–25 秒，按「文件指纹 + dpi + 模型」缓存，重建不会重复识别。
- Word 只取正文：`.docx` 的表格单元格单独成行，页眉页脚、脚注、批注、图片不索引；`.doc` 的自动编号不保留。
- 首次建索引会把整个目录解包并向量化一次；952 个 docx / 57MB 的实测首次建索引 11.3 秒。
- 关键词兜底用字符二元组匹配，个别弱相关查询会命中共享字词；追求精度时让 embedding 服务可用。
- 索引文件放在各库的 `<root>\.dsh-kb`，该目录默认不参与索引。
- 多库一起检索时每个库各取一份候选再合并，库越多一次检索的召回开销越大；只扫某一库时用 `library` 更快。
- 重排会增加一次网络往返，候选数（`candidates`）越大越慢；默认 24 条。
- 素材包是「找对片段」的加速器，不是判断器：年份靠文件名与正文推断，`07-素材金句` 这类汇编文件往往判成「年份未知」；地域靠地名表匹配，正文顺带提一句外省也可能被标成外地。引用前仍需 `kb_read` 核对原文。
- 素材包要跑十几到几十次检索，语义模式下每次检索都要向量化一次查询，耗时随提纲点数线性增长；提纲控制在 6 条以内比较合适。

## 已验证情况

- 单元测试 53 项（`test/kb.test.mjs` 13 + `test/ui.test.mjs` 20 + `test/pdf.test.mjs` 5 + `test/libraries.test.mjs` 5 + `test/packet.test.mjs` 10）：切块与行号、关键词检索与阈值、目录越界拦截、语义检索全链路（对着本地伪造的 `/api/embed` 服务）、服务不可用时退回关键词、索引增量复用、索引目录不被自我索引、删除文件后条目消失、`apply` 注册与卸载、`.docx` 解包、按文件头识别改名的 Word 文件、损坏文件给出可读错误；重排协议与降级、凭据库读写与环境变量优先级、凭据服务晚装配仍可用（惰性解析）、配置合并、HTTP 接口七个端点、保存设置先回话再写配置、非回环请求 403、未配置目录时 state/docs 仍可用、保存失败经 `/state.saveError` 暴露、测试按钮用表单里未保存的配置与密钥、embedding 网关 5xx 时重试并自动拆半；PDF 的 ToUnicode 还原、扫描件报错、非 PDF 文件报错、改名成 `.docx` 的 PDF 仍按文件头解析；多库的 id 稳定性与去重、跨库聚合状态与文件清单、按库名/库 id 定向、跨库检索合并与同名文件要求指定库、空配置不崩；素材包的年份三来源、地域五档、四类归集、提纲拆条、查询编排（三通道 + 定向 + 去重）、同文件去重窗口、每类上限、卡片四字段齐全、空输入 400、`kb_packet` 输出带年份与核对提示。
- 真实库实测：`F:\领导讲话知识库` 下 952 个 docx 中 921 个正常解包，另 31 个是旧版 `.doc` 改了后缀；补上 `.doc` 解析后，35 个 OLE2 文档（含 4 个 `.doc`、1 个 `.wps`）全部解析成功，平均 2523 字/篇。加上 PDF 支持后索引为 957 个文件 / 6850 个片段（PDF 贡献 12 个片段，另有 2 个 xls、1 个 xlsx 未解析并已列出），首次建索引 11.3 秒，增量重建 1.7 秒。
- 在本机运行中的 GUI 上实测：`/state`、`/docs`、`POST /search` 均返回正常结果，侧边栏 `local-kb` 与主面板 `local-kb` 两个槽位都已注册并 active；保存设置一次（空改动）成功写回配置并重载插件，`/state` 随后恢复。
- 用真实 API（SiliconFlow）验证过：`Qwen/Qwen3-Embedding-4B` 单次探活 179ms、维度 2560；整库 6838 片段批量向量化 442 秒一次通过，检索延迟约 0.3 秒；`Qwen/Qwen3-Reranker-4B` 探活 154ms、带重排的检索约 1.4 秒，重排分数（0.91–0.99）与原始余弦分（0.49–0.62）顺序一致但区分度更高。首次整库向量化时上游网关返回过一次 502，由此补上了批量重试与拆半逻辑。
- 素材包在真实库上跑过：`文旅融合与乡村振兴` + 3 条提纲 → 48 张卡片（四类各 12）· 检索 13 次 · 候选 104 条 · 去重后 86 条 · 11.5 秒，其中 12 条标为疑似外地、30 条年份未知；`乡村文化振兴`（每类 3 张、每条查询 4 条候选）→ 11 张卡片 · 5 次检索 · 5.3 秒，卡片正确标出 `外地·湖南`、`省级·本省`、`县区·蕉城区`、`市级·本级`。
